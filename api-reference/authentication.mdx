Every request to the NeoXZ API must include a valid API key as a Bearer token in the `Authorization` header. Requests that omit a key, pass an expired key, or use a key without the required scope will be rejected before any business logic runs. You can generate and manage API keys from your [NeoXZ dashboard](https://app.neoxz.com/settings/api-keys).

## Authorization Header

Include your API key in every request using the `Authorization` header in the following format:

```
Authorization: Bearer YOUR_API_KEY
```

Replace `YOUR_API_KEY` with the key you generated in the dashboard. Keys are prefixed with `nxz_` so you can identify them at a glance (e.g., `nxz_live_sk_abc123...`).

<Warning>
  Never send your API key as a query parameter (e.g., `?api_key=...`). Query strings are routinely captured in server access logs, browser history, and CDN logs — exposing your key to anyone with access to those records. Always use the `Authorization` header.
</Warning>

## Example Request

The examples below show how to make an authenticated `GET` request to retrieve a list of resources.

<CodeGroup>

```bash curl
curl https://api.neoxz.com/v1/resources \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

```javascript JavaScript
const response = await fetch("https://api.neoxz.com/v1/resources", {
  method: "GET",
  headers: {
    "Authorization": `Bearer ${process.env.NEOXZ_API_KEY}`,
    "Content-Type": "application/json",
  },
});

const data = await response.json();
console.log(data);
```

```python Python
import os
import requests

response = requests.get(
    "https://api.neoxz.com/v1/resources",
    headers={
        "Authorization": f"Bearer {os.environ['NEOXZ_API_KEY']}",
        "Content-Type": "application/json",
    },
)

data = response.json()
print(data)
```

</CodeGroup>

<Note>
  Store your API key in an environment variable (e.g., `NEOXZ_API_KEY`) rather than hard-coding it in your source code. This keeps credentials out of version control.
</Note>

## Scopes

Each API key is issued with one or more **scopes** that define what operations it can perform. Apply the principle of least privilege — use a key with only the scopes your integration actually needs.

| Scope   | Description                                                                                   |
|---------|-----------------------------------------------------------------------------------------------|
| `read`  | Allows `GET` requests to retrieve resources, users, and configuration. No write access.       |
| `write` | Allows `POST`, `PUT`, and `PATCH` requests to create and update resources. Includes `read`.   |
| `admin` | Full access including destructive operations (`DELETE`) and account-level settings management. Includes `read` and `write`. |

You configure the scope when you create a key in the dashboard. You cannot elevate a key's scope after creation — generate a new key if you need broader permissions, then revoke the old one.

## Authentication Errors

When authentication fails, the API responds with a `4xx` status code and a JSON error body. Use the `error` field to distinguish between different failure modes and handle them accordingly.

| Status | Error Code          | Cause                                                                 |
|--------|---------------------|-----------------------------------------------------------------------|
| `401`  | `unauthorized`      | The `Authorization` header is missing, malformed, or the key is invalid/revoked. |
| `403`  | `forbidden`         | The API key is valid but does not have the scope required for this operation.     |

**Example 401 error response**

```json
{
  "error": "unauthorized",
  "message": "Invalid or missing API key.",
  "request_id": "req_xyz789"
}
```

**Example 403 error response**

```json
{
  "error": "forbidden",
  "message": "Your API key does not have the 'write' scope required for this operation.",
  "request_id": "req_xyz790"
}
```

## Rotating Your API Key

If you suspect your API key has been compromised, rotate it immediately:

<Steps>
  <Step title="Generate a new key">
    Go to **Settings → API Keys** in the NeoXZ dashboard and create a new key with the required scopes.
  </Step>
  <Step title="Update your integration">
    Deploy the new key to all services and environment variables that use the old key.
  </Step>
  <Step title="Revoke the old key">
    Return to **Settings → API Keys** and revoke the compromised key. It will be rejected immediately on all subsequent requests.
  </Step>
</Steps>
