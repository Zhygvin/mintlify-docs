The NEOXZ Wallet Recovery SDK is a drop-in replacement for seed-phrase backup. It splits private keys across the user's trusted contacts, a recovery key, and NEOXZ identity attestation using 3-of-5 Shamir Secret Sharing, so losing a device never means losing funds.

## Why Seed Phrases Must Die

Seed phrases are the single largest source of self-custody loss. Industry data shows:

- Billions of dollars in crypto are permanently lost to forgotten or destroyed seed phrases
- Phishing attacks against seed phrases drain exchanges and individual wallets weekly
- "Not your keys, not your coins" is incompatible with mass adoption while seed phrases exist
- Hardware wallets improve storage but still rely on seed-phrase recovery as the fallback

DSS Wallet Recovery replaces the seed phrase without reintroducing custodial risk. The user still holds their keys. The keys are just recoverable through reality-anchored identity instead of a 12-word string on paper.

## How It Works

<Steps>
  <Step title="Key generation on device">
    Private keys are generated inside the device Secure Enclave. They never leave the hardware boundary.
  </Step>
  <Step title="Shamir split into five shares">
    The key is mathematically split so any 3 of 5 shares reconstruct it; 2 or fewer reveal nothing.
  </Step>
  <Step title="Shares distributed">
    One share each to: the user's primary device, a secondary device, two trusted contacts, and the NEOXZ identity attestation service.
  </Step>
  <Step title="Recovery requires DSS attestation">
    Reconstructing the key requires 3 shares plus a successful DSS triangulation (device + contact + location) proving the person recovering is the original owner.
  </Step>
</Steps>

See [Multi-Device Recovery](/dss/multi-device-recovery) for the full protocol detail.

## Integration Example

<CodeGroup>

```typescript TypeScript
import { WalletRecovery } from "@neoxz/wallet-recovery";

const wallet = new WalletRecovery({
  apiKey: process.env.NEOXZ_API_KEY!,
  chain: "ethereum",
});

// User creates wallet
const { address, deviceShare } = await wallet.create({
  userId: "user_abc123",
  trustedContacts: ["+15551234567", "+15559876543"],
});

// Later: user loses device
const recovered = await wallet.recover({
  userId: "user_abc123",
  dssAttestation: await dss.attestIdentity("user_abc123"),
});

console.log("Wallet restored:", recovered.address);
```

## Why This Wins Against Alternatives

| Approach | Weakness | DSS Recovery Advantage |
| --- | --- | --- |
| 12-word seed phrase | User loses or is phished | No seed phrase exists to lose or phish |
| Hardware wallet alone | Device breaks or is destroyed | Recovery requires only 3 of 5 shares |
| Social recovery (contacts only) | Collusion risk, no identity binding | DSS triangulation prevents impersonation |
| Centralized custody | Not actually self-custody | NEOXZ holds 1 of 5 shares; cannot act alone |
| MPC (multi-party computation) | Complex integration, high cost | Standard Shamir, simple SDK, known cryptography |
