NEOXZ Compliance Attestation turns the DSS protocol's handshake stream into audit-ready reports suitable for SEC registration, tax withholding compliance, SOC 2 audits, HIPAA attestations, and board reviews. Each report carries the same verification seal as the [NEOXZ Telemetry Report](/dss/proof-of-work): VERIFIED / NEOXZ-SEC / AUTH-100%.

## Why This Product Exists

Regulated industries spend six to seven figures per year proving who did what, when, and from where. Traditional authentication logs do not survive adversarial audit because:

- SMS and email OTPs can be intercepted, so they cannot anchor identity
- Session tokens can be stolen and replayed, so they cannot anchor time
- IP geolocation can be spoofed, so it cannot anchor place

DSS handshakes solve all three. Every 3-second handshake is cryptographically signed by hardware Secure Enclave, carries a reality-anchored trust score, and is immutably sealed on the discrete ledger.

## What's in a Report

Each attestation report contains:

| Section | Contents |
| --- | --- |
| Report identity | Unique report ID, date range, operator account, cloud region, Sovereign tier |
| Core KPIs | Handshake volume, average latency, compute usage, active node count |
| Vector telemetry | Per-user trust-score breakdown across device, contact, and location vectors |
| Anomaly log | All step-up triggers, failed handshakes, and session terminations with reason codes |
| Mesh status | Health of integrated services (identity providers, telemetry pipeline, perimeter sensors) |
| Audit events | Timestamped record of material actions keyed to responsible user |
| Cryptographic seal | DSS hash, protocol node identifier, and manifest ID |

## Delivery Format

Reports are delivered in three synchronized formats:

<Steps>
  <Step title="Signed PDF">
    Human-readable report with the full seal, suitable for direct submission to regulators.
  </Step>
  <Step title="JSON manifest">

    Report root hash anchored to the discrete ledger. Any party can independently verify the report has not been altered after issuance.
  </Step>
</Steps>

## Verification Chain

Any recipient of a NEOXZ attestation report can independently verify its authenticity:

<Steps>
  <Step title="Extract the DSS hash">
    Pull the report seal (e.g., `0xa7b9c24e88ff102b543789ccba01e4598d7612f043e871da6c2304918e951bfa`).
  </Step>
  <Step title="Query the discrete ledger">
    Submit the hash to the public ledger endpoint. Receive the issuance timestamp and manifest ID.
  </Step>
  <Step title="Verify the manifest signature">
    Confirm the manifest signature chains to the NEOXZ Engineering root key published in the trust bundle.
  </Step>
  <Step title="Reconstruct the Merkle root">
    Hash the report payload. Confirm the computed root matches the on-chain anchor.
  </Step>
</Steps>
